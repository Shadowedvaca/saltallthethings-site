# Salt All The Things 0.0.2

## Highlights

- Completes the first production container cutover with a dedicated private SATT PostgreSQL container, matching the established application-plus-database pattern used by the other hosted projects.
- Preserves the current host database and legacy systemd runtime as an immediately recoverable rollback source during the first-cutover observation window.

## Fixes/Changes

- Replaces the unreachable application-container-to-host-database path from the unshipped 0.0.1 attempt with a private Compose network shared only by the SATT application and database services.
- Gives production an explicitly named persistent database volume and keeps PostgreSQL unpublished from the host network.
- Creates separate verified preflight and stopped-runtime backups, restores the final backup into a fresh volume, and compares secret-safe authentication and stable-data fingerprints before and after migrations.
- Extracts the public frontend from the exact immutable application image and promotes it atomically so browser assets and backend behavior come from the same commit.
- Keeps failed database volumes and verified dumps for investigation instead of automatically deleting or destructively restoring data.
- Switches the 03:00 UTC SATT backup cron to verified private-container dumps after successful cutover while preserving the host-database cron for rollback.
- Records that `prod-v0.0.1` reached production preflight but failed before runtime cutover, migrations, or GitHub Release publication and therefore was never shipped.

## Validation

- Focused production backup tests verify explicit preflight/final phases, SATT-schema-only custom dumps, restore-list validation, digest-only reporting, and rejection of invalid phases.
- Static delivery tests verify the private two-service production topology, named-volume isolation, absence of a published database port, immutable tag gate, backup/restore ordering, fingerprint comparisons, frontend asset swap, and non-destructive recovery contract.
- The complete safe local suite passed with 143 tests; 66 database-backed cases skipped safely because no isolated local `TEST_DATABASE_URL` was configured. JavaScript syntax/contracts, changed YAML, release metadata, and both Bash entrypoints also passed.
- Pull-request validation passed the full isolated migration/database suite and the production-image fresh-database, schema backup/restore, fingerprint continuity, migration recovery, immutable health, and forced runtime-recovery checks.

## Deployment/Migrations

- No new Alembic application-schema revision is introduced; the restored database is upgraded through the existing migration head before traffic is accepted.
- The first cutover requires a short SATT-only outage after the final backup while the fresh production database volume is initialized, restored, migrated, fingerprinted, and health-checked.
- The source dump is limited to the SATT schema. The host PostgreSQL database remains unchanged and the new database service has no published port.
- Production server configuration must provide separate legacy-source and private-container database settings without exposing their values. Ordinary branch pushes and merges still cannot deploy production.

## Rollback

- Any failed final backup, restore, migration, fingerprint, local health, asset promotion, or public health check stops only the failed SATT containers, restores the prior static directory, checks out the recorded prior commit, and restarts the unchanged SATT systemd runtime against the unchanged host database.
- The failed named volume and verified dumps are retained. Deleting that volume, restoring a dump over an existing database, or retiring the host runtime requires separate explicit approval.
- After a successful first cutover, retain the host database, systemd unit, prior static directory, final verified dump, prior backup cron, and recorded rollback state throughout the observation window.

## Known Limitations

- Version 0.0.2 is not shipped until the corrected commit passes pull-request validation, isolated development and test promotion, a separately approved immutable production tag, and public production verification.
- The first cutover intentionally duplicates the SATT dataset into a new private volume; cleanup of the unchanged host source is deferred until the rollback window closes and receives explicit approval.
- Production OAuth and AI behavior remain dependent on the existing server-side configuration and database content; no credential values are copied into repository files, logs, or release records.
