# Salt All The Things 0.0.5

## Highlights

- Establishes the server-enforced Top 3 privacy foundation: reusable shared concepts, one concept per episode, account-owned private picks, external-result storage, and viewer-specific reveal records.
- Adds authenticated AI assistance for turning host concept notes into an editable shared Top 3 definition with validated fictional examples and save-ready provenance.
- Adds a responsive, keyboard-accessible Top 3 workshop and bank for manual creation, explicit AI-proposal acceptance, editing, filtering, and concept lifecycle management.

## Fixes/Changes

- Adds authenticated, viewer-scoped Top 3 APIs. Owners receive their full three-pick submission; other account viewers, including administrators, receive contributor and completion metadata without hidden picks or discussion notes.
- Keeps every Top 3 concept, assignment, submission, and reveal out of the general browser export, import, and shared cache contracts.
- Documents the ownership, redaction, reveal, lifecycle, and rollback rules in `docs/top3-privacy.md`.
- Adds `POST /api/ai/top3-concept`, using the configured server-side Claude or OpenAI provider to preserve supplied names or propose a missing name, refine the description and rules, and return exactly three distinct ranked examples.
- Enforces a strict four-field provider response, one bounded repair attempt, secret-safe credential and provider failures, and explicit AI provider/model/time provenance. Generation returns a proposal only and cannot create or infer a host, guest, or listener submission.
- Adds `/top3.html` and authenticated navigation for brainstorming or editing shared definitions, regenerating AI proposals, and explicitly saving only after review. Every example is labeled as fictional and separate from participant picks.
- Supports search, active/retired filters, edit, retire, restore, and guarded delete actions with visible validation, provider, conflict, and save recovery messages. The page keeps its own revision-aware in-memory cache instead of placing Top 3 data in shared browser storage.
- Extends the concept-list response with assignment-only episode ID/title/number metadata so the bank can show usage without exposing picks or discussion notes. The workshop and banking workflow is documented in `docs/top3-workshop.md`.

## Deployment/Migrations

- Adds reversible Alembic revision `0008`, creating four Top 3 tables with foreign keys, participant-shape and ranked-pick checks, and a partial uniqueness constraint for one account submission per assignment.
- Development, test, and pull-request workflows now require migration head `0008`; pull-request container validation rehearses `0008` to `0007` to `0008`.
- AI concept generation adds no schema revision; accepted proposals use the existing `0008` concept provenance columns and are persisted only through the explicit concept-save API.
- The Top 3 Bank adds no schema revision. Production asset cutover now includes `top3.html`; the page and script are served from the same immutable application image as the API.

## Rollback

- Application rollback requires code compatible with migration `0008`. Downgrading to `0007` drops all Top 3 tables, so operators must first verify an environment-specific backup and obtain approval before restoring data.
- The AI generation endpoint can be rolled back to the prior application commit without a database downgrade; concepts already saved with valid AI provenance remain compatible with the `0008` data contract.
- The workshop UI and assignment metadata projection can be rolled back with the application image without a database downgrade. Concepts created through the page remain valid `0008` records.

## Known Limitations

- Episode controls, deliberate reveal UI/API, external-entry UI/API, and Spotify composition remain in ordered children #28 through #30.
- Provider-backed generation requires an AI credential configured on the server. Automated tests mock providers, and deployment smoke tests deliberately avoid external AI calls while verifying authentication, participant-shaped input rejection, credential containment, and the actionable missing-credential path when no provider credential is configured.
- Per delivery-slice approval, manual UI verification is intentionally deferred until all selected children are complete; automated browser/static validation and isolated development deployment smoke remain required for each child in the meantime.
