# Salt All The Things 0.0.4

## Highlights

- Adds the server-owned Song Bank data contract and persistence foundation for manually curated episode songs while keeping private host notes authenticated and out of public episode responses.

## Fixes/Changes

- Stores each song as an independent record with artist, title, validated official YouTube URL, private notes, lifecycle state, optional episode-idea assignment, and server-owned timestamps.
- Adds authenticated, revision-guarded Song Bank read/write, import/export, assignment, replacement, removal, retirement, restoration, and deletion behavior.
- Enforces one song per idea and one active idea per song through application transactions and database constraints; idea deletion frees its song in the same transaction.
- Extends the browser storage contract with Song Bank cache, import/export, and atomic lifecycle methods without adding a public Song Bank response.

## Validation

- Song contract and Alembic-chain unit coverage passes locally, including supported and rejected YouTube URL forms with network access disabled.
- Python compilation, Song Bank lint checks, JavaScript syntax, and the browser storage contract pass locally.
- Full isolated PostgreSQL migration, database lifecycle/concurrency tests, production image inspection, pull-request validation, and isolated development deployment evidence are recorded after those gates complete.

## Deployment/Migrations

- Adds Alembic revision `0007`, which creates `satt.songs` with lifecycle, foreign-key, check, and uniqueness constraints.
- Development, test, and pull-request migration verification advances to head `0007`; application startup continues to apply migrations before serving traffic.
- Production continuity fingerprinting treats the additive table as empty before migration and includes every Song Bank field through one-way counts and SHA-256 evidence after migration.
- No external YouTube, AI, OAuth, Drive, DNS, environment, secret, or production configuration change is required.

## Rollback

- Application rollback remains the prior immutable commit through the documented non-production Compose recovery path.
- Downgrading `0007` to `0006` drops only the new `satt.songs` table, but permanently removes Song Bank records; export or database backup is required before a downgrade once song data exists.

## Known Limitations

- This child provides the data, API, and browser-storage foundation only. The authenticated Song Bank page, episode preparation controls, and Spotify-ready song block remain in ordered children #22, #23, and #24.
- YouTube URLs are validated locally as official HTTPS watch, short, live, embed, or `youtu.be` video links; the application intentionally performs no metadata lookup or remote availability check.
