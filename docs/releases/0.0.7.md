# Salt All The Things 0.0.7

## Highlights

- Makes the initial AI-generated Top 3 proposal save path resilient to unrelated server revision changes without weakening real Top 3 concurrency protection.
- Keeps the homepage subtitle and Explore prompt separated as the hero content wraps across desktop, tablet, and mobile layouts.

## Fixes/Changes

- Reconciles the canonical Top 3 Bank and current server revision immediately after AI generation while preserving the generated proposal in the workshop.
- Retries a conflicted bank mutation once only when the canonical Top 3 concept and assignment state is unchanged; an actual bank change remains visible and requires deliberate review and retry.
- Keeps one stable draft concept identifier across conflict retries so a recovered save cannot create a second proposal record.
- Preserves generated form values and provenance when a genuine conflict reloads the latest bank.
- Places the homepage Explore prompt in the hero's responsive content flow with bounded spacing instead of anchoring it over variable-height content.
- Aligns the shared Codex and Claude Code repository instructions with the Solo Development standard, including independent validation/integration inputs, cumulative Parent-cadence delivery, development-complete approval before any due human UI validation, four explicit gate types, and Mike-only exact version authority.
- Blocks production before SSH unless GitHub Actions proves the exact tagged SHA completed the SATT test deployment successfully from a `main` push; main ancestry alone no longer satisfies test provenance.
- Establishes canonical testing instructions, enforced Python coverage ratchets, and isolated Playwright journeys with bounded failure evidence.

## Validation

- Adds browser-contract coverage for an unrelated revision advancing between generation and save, including canonical reconciliation, bounded retry, and one persisted concept.
- Adds a two-client regression path that forces a genuine bank conflict, verifies the proposal remains intact, and verifies a deliberate retry uses the same identifier and creates no duplicate.
- Adds API coverage confirming AI proposal generation does not mutate the shared server revision or Top 3 concept state.
- Adds a homepage layout contract that prevents the Explore prompt from returning to absolute positioning outside the hero content flow.
- Confirms rendered subtitle-to-Explore separation with no horizontal overflow at 1440x900, 1024x768, 768x1024, 390x844, and 360x640 viewports, plus enlarged browser text.
- Passes synchronized-entry-point, required-reference, Markdown-link, diff-whitespace, and stale-process-language checks for the Solo Development documentation alignment.
- Passes release-contract validation, parsing of every GitHub Actions workflow, and all 30 focused delivery, release, repository-security, and version tests for the process/workflow change.
- Passes pull-request validation with the complete Python 3.12 suite, fresh isolated PostgreSQL migrations, browser contract checks, production-image inspection, migration rollback/recovery, backup restore, and runtime recovery checks.
- Passes the isolated development deployment and authenticated environment smoke checks; public health reports `development`, version `0.0.7`, and the exact deployed branch commit.
- Adds repository-document checks that keep the AI entry points identical, require the canonical testing references, and reject broken local documentation links.
- Adds zero-retry Chromium coverage for the responsive public hero and the unauthenticated Show Management boundary while blocking unexpected external network requests.
- Establishes the overall Python coverage ratchet at the complete isolated-suite measurement of 63.06% and changed executable application lines at 90.0%; either floor may stay fixed or rise, but cannot be lowered merely to pass CI.

## Deployment/Migrations

- No schema migration or data-contract migration is required; the existing Alembic head remains revision `0009`.
- Development and later approved environments must report version `0.0.7` and the exact deployed commit through health metadata.
- The production job now requires read-only Actions metadata access so it can prove the exact tagged commit completed the isolated test deployment before any production connection.
- Pull-request validation now installs a pinned browser runner and retains failure-only browser artifacts for seven days; no schema or runtime configuration changes are introduced.

## Rollback

- Redeploy the previously validated application commit for the browser changes; no database rollback is required. Correct a broken provenance query through the normal reviewed workflow path rather than bypassing the fail-closed production gate.

## Known Limitations

- A real concurrent Top 3 Bank change intentionally requires the user to review the refreshed canonical bank and retry the preserved proposal.
- Live AI generation remains dependent on a separately configured, environment-specific server-side provider credential; automated validation mocks the provider.
- On short viewports the hero grows with its content, so the Explore prompt may require scrolling rather than being forced over the subtitle.
- Production promotion now depends on GitHub Actions run metadata being available; an API or permission failure blocks production before SSH.
- Automated browser coverage currently protects the public responsive hero and unauthenticated Show Management boundary; later UI children must extend the applicable parent journeys.
