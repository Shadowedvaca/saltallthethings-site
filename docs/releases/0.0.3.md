# Salt All The Things 0.0.3

## Highlights

- Corrects the two production-only verification gaps discovered during the failed, unpublished 0.0.2 cutover attempts while preserving the proven backup, restore, fingerprint, and rollback boundaries.

## Fixes/Changes

- Gives Alembic verification processes the same private server-side database configuration used during container startup without adding a database URL to Compose configuration.
- Normalizes the approved legacy host alias to host loopback for host-side source fingerprinting and continues to reject external database hosts.
- Retains `prod-v0.0.2` as immutable failed-attempt evidence; the corrected release uses a new `prod-v0.0.3` tag after development and test approval.

## Validation

- Focused unit and static delivery tests cover private URL encoding, allowed legacy-host normalization, external-host rejection, and post-start Alembic configuration.
- The complete safe local suite passed 148 tests; 66 database-backed cases skipped safely because this workstation has no configured isolated `TEST_DATABASE_URL`, Docker runtime, or PostgreSQL service.
- Python compilation, all browser JavaScript syntax/contracts, release metadata, shell syntax, and diff integrity passed locally.
- Pull-request validation passed the full isolated PostgreSQL suite plus image inspection, fresh-database migration, the exact post-start Alembic check, backup/restore fingerprint continuity, immutable health metadata, and forced runtime recovery.
- Isolated development deployment passed environment/version/commit health checks, migration revision 0006, ephemeral registration/login/protected/public smoke coverage, persistence checks, and temporary-identity cleanup.
- Isolated test deployment evidence remains required before production promotion.

## Deployment/Migrations

- No new Alembic schema revision is introduced. The existing migration head is verified from a fresh process after container startup using only private server-side database fields.
- Production remains on the prior healthy systemd runtime until a separately approved `prod-v0.0.3` deployment completes.

## Rollback

- Failed cutovers continue to remove only SATT containers and their network, retain the failed database volume and verified dumps, restore the prior checkout/static assets when applicable, and restart the unchanged systemd runtime.
- The retained unused candidate volume from the failed 0.0.2 attempt is removed only at the approved recovery gate after its identity, live runtime health, and verified backups are reconfirmed.

## Known Limitations

- Version 0.0.3 is not shipped until the exact corrected commit passes pull-request validation, isolated development and test promotion, explicit production-tag approval, cutover verification, and public production smoke testing.
