# Salt All The Things 0.0.1

## Highlights

- Establishes the Foundation release governance baseline and a single cumulative
  release record for issues #4 through #15.
- Invalidates the database credential that had been exposed in tracked
  documentation without logging either the old or replacement value.
- Makes browser and backend configuration environment-aware so one immutable
  source revision can run in local, development, test, and production.

## Fixes/Changes

- Defines `VERSION` as the authoritative application version and reports `0.0.1`
  through FastAPI metadata and `/api/health`.
- Removes the invalid credential from current tracked documentation.
- Documents the branch, approval, promotion, secret-handling, milestone, and
  parent/child issue contracts for the Foundation release.
- Repairs mocked AI/Drive tests so they reflect server-side OAuth requirements
  and the existing album-art archive behavior.
- Replaces production and legacy-staging browser API origins with same-origin
  `/api` and `/public` routing.
- Adds canonical local, development, test, and production origins plus explicit
  `ENVIRONMENT`/`DATABASE_ENVIRONMENT` ownership checks.
- Rejects production web origins and implicit Google OAuth use in
  non-production; external-service smoke tests require an explicit opt-in and
  still require isolated credentials and Drive resources.
- Extends `/api/health` with environment and commit metadata while returning no
  configuration secrets.
- Adds a safe local startup mode that serves only the public frontend assets
  alongside FastAPI and does not expose `.env`, source, or repository metadata.

## Validation

- The authorized rotation workflow confirmed by one-way comparison that the
  tracked credential matched the active SATT database credential before rotation.
- The replacement credential authenticated, the invalidated credential was
  rejected, and the SATT service and health endpoint remained healthy.
- The rotation workflow ran from commit
  `117fdf9f99744b3ca583432c55ee7d9f9cdc333a`; its normal production deployment
  job was skipped.
- The complete locally available pytest suite passed: 64 tests passed and 51
  database-backed tests were safely skipped because no isolated
  `TEST_DATABASE_URL` is configured.
- The focused AI/Drive regression modules passed all 16 tests with external
  services mocked.
- Python compilation, seven plain-browser JavaScript syntax checks, workflow
  YAML parsing, release/version contract tests, the repository secret
  regression check, and the Alembic revision-chain inspection passed.
- After issue #5, the complete locally available suite passed 75 tests; 51
  database-backed tests were safely skipped because no isolated
  `TEST_DATABASE_URL` is configured.
- Thirteen focused environment, same-origin, local-static, and health metadata
  tests passed. Python compilation, all repository JavaScript syntax checks,
  workflow YAML parsing, and the single Alembic head inspection also passed.

## Deployment/Migrations

- No application deployment or database migration was performed.
- The only production operation was the explicitly authorized SATT database-role
  credential rotation and corresponding SATT environment-file update.
- Database execution, container validation, pull-request CI, and isolated
  development deployment are deferred to the ordered children that create those
  facilities.
- Issue #5 has no schema or data-contract migration. Before any environment is
  started from this revision, its server-side configuration must set matching
  `ENVIRONMENT` and `DATABASE_ENVIRONMENT` values, its canonical `SITE_URL` and
  CORS origin, and the deployed `COMMIT_SHA`.

## Rollback

- The rotation job was transactional at the operational level: any failed
  authentication, restart, or health check restored the prior role credential
  and SATT environment file before restarting the service.
- The completed rotation must not be rolled back to the invalidated credential.
- Issue #5 can be rolled back by reverting its focused commit before promotion.
  A rollback must preserve environment-specific server configuration and must
  not restore production or legacy-staging API URLs in non-production browser
  assets.

## Known Limitations

- Isolated development and test environments are not provisioned until issues
  #11 and #12, so this child cannot yet be deployed through `deploy-dev.yml`.
- Containerized database/migration validation and pull-request CI are not
  available until issue #6.
- GitHub development, test, and production environment mutations and the
  standard repository secret values remain deferred until their consuming
  workflows and isolated hosts are provisioned and separately authorized.
- The legacy push-to-`main` production workflow remains until the gated cutover
  in issue #14.
- Development and test hosts, isolated databases, environment configuration,
  and deployment smoke evidence remain unavailable until issues #11 and #12.
  No live environment was changed or contacted for issue #5.
- The `COMMIT_SHA` health value remains `unknown` until later deployment
  workflows inject the immutable revision.
